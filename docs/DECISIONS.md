# Keputusan Teknis HariMu (Android)

1. **Arsitektur Registry-Driven (`ToolRegistry` & `ToolContract`)**
   Semua tool terdaftar terpusat di `ToolRegistry` dan dirender secara dinamis oleh `ToolScreen` berdasarkan `InputSpec` dan `ToolParam`, sedangkan tool interaktif kompleks (Voice Recorder, Image Matrix, Equalizer 10-Band, Key Vault, Backup `.omni`) memakai layar studio khusus.

2. **Engine On-Device Tanpa Biner GPL**
   - **Media/Video**: Jalur utama Media3 `Transformer`/`MediaCodec` + Android native `MediaExtractor`, `MediaMuxer`, `MediaMetadataRetriever`; FFmpeg hanya untuk format/filter yang tidak tersedia di Media3, memakai `dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.9` berlisensi **LGPL v3.0** (tanpa `libx264`/`libx265`/`vidstab`). Jadi tetap **tanpa biner GPL**, tetapi bukan "tanpa dependensi FFmpeg" — rincian di butir 6 dan 19.
   - **Audio DSP**: Memakai `MediaCodec` PCM decoder + DSP Kotlin langsung (gain, trim, mix/concat, manipulasi kanal, silence remover, reverse, echo, fade, waveform PNG) serta `android.media.audiofx.Equalizer` dan `AudioRecord` / `TextToSpeech`.
   - **Gambar**: Memakai `Bitmap`, `Canvas`, `ColorMatrix`, `Matrix`, `ExifInterface`, dan klasterisasi warna `K-Means`.
   - **PDF**: Memakai Android native `PdfRenderer` dan `PdfDocument` (merge, split, rotate, extract, image-to-PDF, PDF-to-image, watermark, page numbering, pixel-diff comparison).
   - **Konverter & Kripto**: Memakai `java.util.zip`, PBKDF2 + AES-256-GCM (`.hzm` & `.omni`), `AndroidKeyStore` + JCA (AES-256, ECDSA P-256, RSA-2048), serta parser native `kotlinx.serialization.json` (JSON/XML, CSV/TSV, Markdown/HTML, GeoJSON/KML, ASCII/Binary STL→OBJ).

3. **Toolchain Build & Analisis Statis (Fase 0)**
   - **AGP `9.1.1` + Kotlin `2.2.10` + KSP `2.3.5`**: Memakai dukungan Kotlin bawaan AGP 9 tanpa plugin terpisah `org.jetbrains.kotlin.android`.
   - **Style & CI**: `.editorconfig` dan `config/detekt/detekt.yml` disiapkan di repo; GitHub Actions (`.github/workflows/android-ci.yml`) menjalankan `ktlint`, `gradle assembleDebug`, `gradle testDebugUnitTest`, dan `gradle lintDebug` (repo tanpa wrapper; CI memasang Gradle 9.3.1 lewat `gradle/actions/setup-gradle`) tanpa menambahkan plugin Gradle Detekt 1.x yang berpotensi bentrok dengan Kotlin 2.2.

4. **Fitur Cloud & Model Besar**
   Tool yang bergantung pada backend Cloudflare Worker atau model ML unduhan besar (seperti `CORE-02` Prompt Video Gen, `IMG-21` AI Image Gen, `PDF-06` PDF↔Office LibreOffice) tidak di-stub dengan respons palsu; konfigurasi endpoint S3/R2/Worker tersedia di Setelan saat backend disambungkan.

5. **Infrastruktur Inti & Antrean Job (Fase 2)**
   - **Katalog Penuh 163 Tool**: `ToolRegistry` mendaftarkan 163 tool unik (9/30/28/47/21/28) sehingga seluruh ID di `02-KATALOG-FITUR.md` dapat dicari, difavoritkan, dan dibuka di `ToolScreen`. *(Dikoreksi di Fase K4: catatan lama "59 tool aktif + 104 `StubTool`" sudah tidak berlaku — `stubVideoTools()`/`stubAudioTools()`/`stubImageTools()` mengembalikan daftar kosong dan tidak ada `StubTool` yang diinstansiasi.)*
   - **Antrean & Pemulihan WorkManager**: `JobManager` membatasi maks. 2 job berat paralel lewat `JobQueuePolicy` (FIFO) yang disinkronkan dengan tabel Room `jobs` (`JobEntity`). Saat `HariMuApp.onCreate()` berjalan, `recoverPendingJobs()` menyelaraskan status `WorkManager` atau menjadwalkan ulang job yang terputus setelah proses dimatikan.
   - **File, SAF & Model ML**: `FileStorageManager` menamai keluaran `HariMu_<tool>_<timestamp>.<ext>`, membersihkan direktori temp saat startup dan setelah tiap job, memeriksa ruang disk bebas sebelum eksekusi, serta mendukung ekspor ke folder default SAF (`OpenDocumentTree`), `MediaStore`, atau `CreateDocument` dan berbagi via `FileProvider`. `ModelManager` menyimpan model lokal di `noBackupFilesDir/models`.
   - **Cloud Connections**: Bagian Cloud Connections di `SettingsScreen` hadir sebagai UI kosong terdaftar yang siap dihubungkan pada P14.

6. **Engine Media: FFmpeg Maintained Wrapper + Media3 Transformer (Fase 3)**
   - **Pengganti `ffmpeg-kit` yang Diarsipkan**: `com.arthenica:ffmpeg-kit-*` resmi pensiun dan dihapus dari Maven Central (awal 2025). Proyek ini memakai fork terpelihara **`dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.9`** (`https://github.com/ffmpegkit-maintained/ffmpeg`, rilis Maven Central 2026) yang mendukung Android SDK 35+ dan **16 KB page size**.
   - **Lisensi LGPL v3.0 (bukan GPL)**: Dipilih varian `ffmpeg-kit-full` berlisensi **LGPL v3.0** (tanpa `libx264`/`libx265`/`vidstab` GPL) agar proyek tetap kompatibel dengan distribusi toko aplikasi tanpa kewajiban copyleft GPL penuh. Untuk encoding H.264/HEVC akselerasi perangkat keras dipakai **Media3 Transformer** (`androidx.media3:media3-transformer:1.11.1`, Apache-2.0) atau codec perangkat keras `h264_mediacodec` bila dibutuhkan.
   - **Dampak Ukuran APK & Split ABI**: File `ffmpeg-kit-full-8.1.9.aar` berukuran **30 MB** dan membundel `.so` 64-bit (`arm64-v8a` ~31,5 MB tak terkompresi, `x86_64` ~38,2 MB tak terkompresi). `app/build.gradle.kts` mengonfigurasi **App Bundle (`bundle.abi.enableSplit = true`)** dan split APK per ABI (`arm64-v8a`, `x86_64`, aktif pada build release/`-PabiSplits`) agar pengguna akhir hanya mengunduh satu ABI.
   - **Fallback Otomatis**: `Media3TransformerEngine` menjalankan Media3 `Transformer` terlebih dahulu pada antarmuka `Flow<ToolProgress>` yang seragam, dan secara otomatis beralih ke `MediaJob` (FFmpeg) bila Media3 gagal pada kombinasi kontainer/codec tertentu (tanpa memicu fallback jika dibatalkan pengguna).

7. **Video Forge Batch 1 (Fase 4)**
   - **Preview ExoPlayer & Strip Thumbnail Trim**: `VID-01` (Trim) dan `VID-21` (Splitter) menampilkan `VideoTrimPreviewCard` berbasis `media3-exoplayer` + `ContentFrame` (`media3-ui-compose:1.11.1`), strip 8 thumbnail hasil downscale `144×96`, serta `RangeSlider` dua arah + tombol `Set Awal`/`Set Akhir` dari posisi playhead.
   - **Batas Keamanan Memori Reverse (`VID-19`) & Loop (`VID-12`)**: Filter FFmpeg `reverse`/`areverse` menyimpan frame tak terkompresi di RAM. Untuk video `> 20 detik` s.d. `3 menit`, `VID-19` memecah video menjadi segmen 12 detik, membalik tiap segmen secara berurutan, lalu menggabungkannya terbalik lewat `-f concat`; video `> 3 menit` ditolak dengan saran memotong terlebih dahulu via `VID-01`. `VID-12` memberi peringatan untuk output `> 3 menit` dan membatasi total durasi output maks. `10 menit`.
   - **Codec LGPL pada Converter (`VID-18`) & Extract Frames (`VID-22`)**: Karena `ffmpeg-kit-full:8.1.9` berlisensi LGPL (tanpa `libx264`), konversi memakai Media3 untuk MP4 atau codec LGPL `libvpx` + `libvorbis` (WebM), `mpeg4` + `libmp3lame` (AVI), serta stream copy/re-muxing MKV; `VID-08` memakai `libmp3lame`. `VID-22` memakai `MediaMetadataRetriever.getScaledFrameAtTime` (maks 1280px) dengan `recycle()` langsung dan streaming ke `ZipOutputStream` (32 KB) untuk mencegah OOM pada video 1080p ≥ 2 menit.

8. **Video Forge Batch 2 & Pro Video Editor (Fase 5)**
   - **Stabilisasi Video (`VID-11`) — Alternatif LGPL `deshake` vs `vidstab`**: Audit isi `libavfilter.so` pada `dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.9` membuktikan `vidstabdetect`/`vidstabtransform` (GPL) tidak disertakan, sedangkan filter LGPL **`deshake`** tersedia. Oleh karena itu `VID-11` memakai `deshake` dengan pilihan kekuatan (`rx`/`ry`: 16/32/48 px, `edge=mirror`) plus opsi pemotongan tepi 8%.
   - **Hapus Logo (`VID-14`) — Alternatif LGPL `gblur`/`avgblur`/`scale+overlay`**: Filter `delogo` dan `boxblur` berlisensi GPL tidak tersedia pada `ffmpeg-kit-full:8.1.9`; implementasi menggunakan ROI `crop` → `gblur` / `avgblur` / pikselasi `scale=neighbor` → `overlay` dengan pratinjau kotak ROI langsung di `ToolScreen` (`RoiLogoPreviewCard`).
   - **Overlay Teks (`VID-15`), Gambar (`VID-17`), Subtitle (`VID-23`), & Color Grading (`VID-26`)**: `VID-15` merender teks bergaya ke bitmap transparan via Android `Canvas`/`Typeface` (menjamin dukungan semua gaya font & kotak latar) lalu memproses via Media3 `OverlayEffect` (`BitmapOverlay`) atau FFmpeg `overlay=enable='between(t,...)'` jika memakai rentang waktu tampil. `VID-23` mem-parsing `.srt`/`.vtt` (`SubtitleParser`) menjadi berkas `.ass` bergaya dan membakar via filter `ass` (dengan font sistem `/system/fonts`). `VID-26` memakai `Contrast`, `HslAdjustment`, `RgbAdjustment`, `RgbFilter` di Media3 dengan fallback FFmpeg `lut3d` (`.cube` tergenerasi untuk preset LUT) + `eq` + `colorbalance`.
   - **Blur Wajah (`VID-25`) — ML Kit Face Detection & Keterbatasan**: Memakai `com.google.mlkit:face-detection:16.1.7` (`PERFORMANCE_MODE_FAST`, `minFaceSize = 0.08f`, `enableTracking()`). Frame di-sampling (1–4 fps, di-downscale ke ≤ 640px lalu langsung `recycle()`) dan digabung menjadi jendela waktu berurutan via `trackingId` + IoU (`>= 0.45`) maksimal 24 segmen `gblur`/`scale+overlay` agar tidak memenuhi memori filter graph. **Keterbatasan yang ditampilkan di UI**: wajah kecil (`< 8%` lebar layar), profil sangat menyamping/menunduk, pencahayaan sangat gelap, atau wajah tertutup masker/objek dapat terlewat; pengguna disarankan memeriksa hasil lewat tombol *Pratinjau Deteksi Wajah* sebelum render.
   - **Pro Video Editor (`CORE-01`) & Room v3**: Layar khusus `VideoEditorScreen` menyimpan proyek ke Room `video_projects` (`AppDatabase` v3, `EditorClipSpec` JSON) agar dapat dilanjutkan. Setiap klip dinormalisasi/trim/kecepatan/rotasi menggunakan ulang `Media3TransformerEngine` (dengan fallback `MediaJob` FFmpeg + `anullsrc` untuk klip tanpa audio saat dicampur klip beraudio) sebelum digabung menjadi MP4.
   - **Catatan Performa & Pengukuran**: Di lingkungan build container tanpa emulator/perangkat fisik (`adb` tidak tersedia), durasi proses diukur pada suite unit/Robolectric (eksekusi graf & pipeline mock < 150 ms) sementara estimasi perangkat keras (Media3 `Transformer` HW vs `mpeg4`/filter graph SW 720p–1080p) menargetkan ±0.3x–1.5x real-time untuk transcode Media3 dan ±1.5x–3x real-time untuk filter SW `gblur`/`chromakey`/`xfade`; benchmark waktu nyata di perangkat fisik Android masih perlu dicatat saat rilis uji perangkat.

9. **Audio Forge Batch 1 (Fase 6)**
   - **Pitch Tanpa Ubah Durasi (`AUD-06`) — Alternatif LGPL `asetrate` + `aresample` + `atempo`**: Pemeriksaan simbol `libavfilter.so` pada `dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.9` memastikan filter GPL `rubberband` tidak tersedia, sedangkan `asetrate`, `aresample`, dan `atempo` tersedia. `AUD-06` menggeser pitch `±12 semitone` lewat `asetrate=sr*2^(st/12),aresample=sr` lalu mengompensasi tempo secara presisi dengan rantai `atempo` sebesar `2^(-st/12)` (`AudioToolMath.buildPitchShiftFilter`).
   - **Normalisasi Loudness 2-Pass (`AUD-12`)**: Tahap 1 menjalankan `loudnorm=I=-16.0:TP=-1.5:LRA=11.0:print_format=json` ke `-f null -` lewat `MediaJob.runStep` (diperluas ke 40 baris log ekor agar blok JSON tidak terpotong), mem-parsing statistik (`input_i`, `input_tp`, `input_lra`, `input_thresh`, `target_offset`), lalu Tahap 2 menerapkan `linear=true` (dengan fallback otomatis ke 1-pass jika klip terlalu singkat untuk JSON).
   - **Validasi Encoder & Batas Sample Rate (`AUD-11`, `AUD-13`, `AUD-14`)**: `DefaultAudioEncoderCapabilities` memvalidasi encoder FFmpeg terkompilasi (`libmp3lame`, `libvorbis`, `libopus`, `flac`, `pcm_s16le`, `aac`) serta `MediaCodecList` perangkat, dan menolak kombinasi tak kompatibel (misalnya `MP3` di atas `48.000 Hz` atau format tanpa encoder) disertai saran format alternatif (`WAV`, `FLAC`, `OGG`, `MP3`).
   - **Editor Metadata ID3 (`AUD-18`) Tanpa Library GPL**: `Id3TagHelper` ditulis murni di Kotlin untuk membaca (`ID3v2.3`/`v2.4`) dan menulis (`ID3v2.3` UTF-16LE + `APIC` sampul gambar) langsung secara *stream* pada MP3 tanpa re-encoding audio, serta fallback ke argumen `-metadata` / `attached_pic` FFmpeg untuk kontainer `.m4a`/`.flac`/`.ogg`/`.wav` tanpa menambah dependensi eksternal baru.
   - **Waveform & Pratinjau Sebelum/Sesudah (`WaveformView`, `AudioWaveformExtractor`)**: Puncak amplitudo diekstrak *streaming* di `Dispatchers.IO` tanpa menampung seluruh PCM di RAM dan di-cache di `LruCache` + disk `cacheDir/waveforms/*.peaks`. `AudioBeforeAfterPreviewCard` memakai ExoPlayer dengan pergantian langsung tab *Sebelum (Asli)* ↔ *Sesudah (Hasil)* dan kontrol potong interaktif untuk `AUD-09`.

10. **Audio Forge Batch 2 & Perbandingan Pratinjau ↔ Ekspor EQ 10-Band (Fase 7)**
    - **Perbandingan Live Preview vs Ekspor FFmpeg (`AUD-02`)**:
      - **Pratinjau Live (Android AudioFX)**: Pada Android 9+ (API 28+), `EqualizerFxController` menggunakan `android.media.audiofx.DynamicsProcessing` (`VARIANT_FAVOR_FREQUENCY_RESOLUTION`, 10 band PreEQ dengan batas *cutoff* geometris `fc * √2`: `44, 88, 177, 355, 707, 1414, 2828, 5657, 11314, 20000 Hz`, input gain preamp `-6..+6 dB`, dan tahap *Limiter* `-0.5 dB`). Pada API 26–27 atau perangkat yang menolak `DynamicsProcessing`, controller otomatis *fallback* ke `android.media.audiofx.Equalizer` (umumnya 5 band) dengan interpolasi log-frekuensi (`AudioBatch2Math.map10BandsToDeviceEqLevels`).
      - **Ekspor FFmpeg Setara**: `AudioBatch2Math.buildEqualizer10BandFfmpegFilter` merangkai 10 filter peaking biquad `equalizer=f=<fc>:t=o:w=1.0:g=<gain>` pada frekuensi pusat ISO `[31, 62, 125, 250, 500, 1000, 2000, 4000, 8000, 16000]` Hz (lebar `1.0 oktaf` agar perpotongan antar-band cocok dengan struktur oktaf PreEQ), diikuti `volume=<preamp>` dan `alimiter=limit=0.9441:attack=5:release=50:level=disabled` (`-0.5 dBTP`).
      - **Hasil Perbandingan Kurva**: Pada `DynamicsProcessing` (API 28+), paritas band pusat dan limiter menghasilkan deviasi nominal **`0.0 dB`** antar titik band ISO (`computeEqParityReport`); pada fallback `Equalizer` 5-band (perangkat/API lama), deviasi terukur muncul di band antara (mis. `31 Hz` atau preset tajam) sekitar **`0.3–1.8 dB`** rata-rata karena jumlah band perangkat keras lebih sedikit, sementara file ekspor tetap menerapkan kurva penuh **10-band** dan dapat langsung dibandingkan A/B lewat `AudioBeforeAfterPreviewCard` di `EqualizerScreen`.
    - **Noise Reduction (`AUD-03`) — `afftdn` vs `arnndn`**: Verifikasi `libavfilter.so` pada `ffmpeg-kit-full:8.1.9` mengonfirmasi filter `afftdn` dan `arnndn` keduanya tersedia, tetapi `arnndn` wajib menerima file bobot `.rnnn` eksternal. Oleh karena itu `AUD-03` memakai `afftdn` (dengan opsi `highpass=f=85` dan 2-stage untuk mode agresif) agar bekerja instan tanpa unduhan model, dan opsi model RNNoise/neural dicatat untuk fase model ML.
    - **Vocal Remover (`AUD-04`) & Kontrak Stem Splitter (`AUD-20`)**: `AUD-04` memakai kanselasi kanal tengah berbasis `pan` + pelindung bass `< 120 Hz` (`lowpass`/`highpass` + `amix`) dan menolak input mono dengan pesan jelas; mode AI Demucs pada `AUD-04` serta `AUD-20` memakai kontrak baru `StemSplitterContract` (`StemSplitterEngine`, `DeferredStemSplitterEngine`, `StemReadiness`) dengan inferensi aktual (ONNX/Cloudflare) dijadwalkan pada **Fase 11**.
    - **Mastering (`AUD-01`), Watermark (`AUD-19`), Reverb (`AUD-25`), & Audio Visualizer (`AUD-28`)**: `AUD-01` mengonversi ambang/ceiling dB ke amplitude linear untuk `acompressor` + `alimiter=level=disabled`; `AUD-19` memakai generator `sine` berinterval `O(1)` atau `apad`+`aloop` untuk klip penanda kustom tanpa membesarkan grafik filter; `AUD-25` menyimulasikan gaung terdiffusi lewat 2 tahap *prime-tap* `aecho` + `lowpass` damping (pengganti `freeverb` yang tidak ada di LGPL); `AUD-28` merender animasi `showwaves` / `showspectrum` / `showcqt` / `avectorscope` ke MP4 memakai encoder LGPL `mpeg4` + `aac`.

11. **Audio Studio Pro Multitrack DAW (`AUD-21`, Fase 8)**
    - **Model Proyek Multitrack**: Menyimpan struktur hierarki `Project -> Track[] -> Clip[]` (dengan URI, offset, trim, gain, pan, mute, solo) langsung ke Room (`audio_projects`) sebagai JSON terkompresi, mendukung hingga 8 track audio.
    - **Timeline DAW & Waveform**: Layar khusus `AudioStudioScreen` menampilkan navigasi timeline horizontal dengan zoom/scroll interaktif, rendering gelombang per klip via `AudioWaveformExtractor` (dijadikan cache LruCache + disk), playhead yang dapat digeser, serta aksi potong, hapus, duplikat, dan penyesuaian offset klip.
    - **Mixer & Pemutaran Real-Time**: Panel mixer menyediakan slider volume dan pan per track, tombol mute/solo, serta volume master. Pemutaran real-time disinkronkan via beberapa pemutar `ExoPlayer` (satu per track/klip aktif) yang dikontrol secara terkoordinasi di `AudioStudioViewModel`.
    - **Ekspor Offline Multitrack**: Menggunakan `AudioStudioEngine` untuk merangkai argumen FFmpeg filter complex (`amix`/`adelay`/`volume`/`pan`) secara akurat, mendukung ekspor offline ke format `WAV`, `MP3`, atau `FLAC` dengan indikator progres real-time.


12. **Image Forge Batch 1 (Fase 9): IMG-01, 03, 05–10, 23–30**
    - **Dekode hemat memori (region/tile)**: `IMG-01`, `IMG-08`, dan `IMG-10` memakai `BitmapRegionDecoder` hanya pada area hasil (`ImageIO.decodeRegionFullRes`), dengan `ImageGeometryMath.cropSourceRegion` memetakan balik 8 orientasi EXIF, sehingga crop 1:1 dari foto 12 MP tidak pernah memuat seluruh bitmap. Operasi yang memang butuh seluruh piksel (rotasi 90/180/270, perspektif, pelurusan, kanvas, penyelarasan) memakai `ImageIO.decodeFullGuarded` dengan batas **48 MP (±192 MB ARGB)** dan pesan yang menyuruh pengguna mengecilkan foto dulu lewat IMG-02 — tidak ada penurunan resolusi diam-diam.
    - **Orientasi & EXIF**: `ImageGeometryMath.cropSourceRegion` diuji golden test untuk orientasi 1, 3, 6, dan 8; `ImageIO.applyOrientation` menangani kedelapan nilai EXIF. Setelah piksel diputar/dipotong, EXIF hasil selalu `ORIENTATION_NORMAL`, dan tag kamera disalin ulang lewat `ImageIO.copyExif` (GPS hanya bila diminta).
    - **Profil warna (ICC)**: segmen APP2 `ICC_PROFILE` pada JPEG sumber dibaca (`ImageIO.readJpegIccProfile`) dan disuntikkan kembali ke JPEG hasil, dipecah otomatis bila > 65.519 byte. Android tidak menyediakan API menulis profil ICC untuk PNG/WebP, jadi profil **tidak** dipertahankan di format itu — dicatat sebagai batas, bukan diklaim.
    - **Geometri murni + golden test**: `ImageGeometryMath` sengaja tanpa import Android dan diuji `app/src/test/java/com/harimu/app/ImageGeometryGoldenTest.kt` dengan angka pasti: crop rasio/zoom/offset, mapping orientasi, `rotatedBounds`, `straightenSafeRect`, homografi identitas & skala, ukuran output perspektif, validasi quad, parser region multi-crop, saliency, alignment SAD, daftar ikon, dan K-Means. Homografi diselesaikan sendiri (eliminasi Gauss 8×8) lalu dimasukkan ke `Matrix.setValues`, sehingga test menguji jalur runtime, bukan salinan rumus.
    - **IMG-06 empat titik drag**: `PerspectivePointsCard` (`feature/toolscreen/`) menampilkan foto + quad yang dapat digeser; tiap gerakan menulis parameter `tlX..blY` (persen) lewat `ToolViewModel.setParam`, dan slider tetap ada untuk penyesuaian presisi. Homografi dipetakan ke persegi output seukuran sisi terpanjang quad.
    - **IMG-08 bukan ML Kit**: `com.google.mlkit:subject-segmentation` tidak dibundel pada fase ini. Auto-crop memakai heuristik saliency lokal (jarak warna tiap sel terhadap rata-rata gambar, ambang + padding dari pengguna) lalu crop resolusi penuh. Batas jujur: latar ramai, kontras rendah, atau subjek sewarna latar bisa salah deteksi; UI menyarankan IMG-01 untuk crop manual. Subject Segmentation/objek ML tetap dijadwalkan **P11**.
    - **IMG-09 translasi saja**: offset dicari dengan SAD pada grid 128×128 (maks geser 1–20%), diskalakan ke resolusi penuh, lalu digabung sebagai rata-rata progresif (alpha `1/k`). Rotasi/skala antar frame tidak dikoreksi; gambar dengan sudut pandang sangat berbeda akan gagal — dicantumkan pada laporan hasil.
    - **IMG-24 paket ikon lengkap**: 5 kerapatan Android legacy, 5 round, 5 adaptive foreground (108dp), Play 512, favicon 16/32/48 + apple-touch 180, 15 entri `AppIcon.appiconset` iOS (termasuk 1024) beserta `Contents.json`, ditambah `mipmap-anydpi-v26/*.xml`, `values/ic_launcher_background.xml`, dan README berisi cuplikan `AndroidManifest.xml` — semuanya dalam satu ZIP (35 PNG).
    - **IMG-26 pratinjau kualitas vs ukuran**: empat tingkat kualitas di-encode ke memori lalu ditabelkan terhadap ukuran sumber; bila target KB diisi, kualitas dicari dengan binary search (7 langkah) dan hasil terkecil dipakai bila target tidak mungkin dicapai.
    - **Matriks dukungan format (IMG-23 & IMG-30)** — sumber tunggal `ImageFormatMatrix`, konverter menolak target tanpa penulis dengan alasan + library yang dibutuhkan:

      | Format | Baca | Tulis | Library / alasan |
      |---|---|---|---|
      | JPG | Didukung | Didukung | `BitmapFactory` / `Bitmap.compress(JPEG)`; ICC + EXIF disalin |
      | PNG | Didukung | Didukung | `BitmapFactory` / `compress(PNG)`; alpha aman, ICC tidak bisa ditulis |
      | HEIC | Terbatas (API 28+, tergantung perangkat) | Tidak didukung | decoder platform; Android tidak punya encoder HEIC |
      | WebP | Didukung | Didukung | `WEBP_LOSSY` semua API; lossless butuh API 30+ |
      | AVIF | Terbatas (API 31+, tergantung perangkat) | Tidak didukung | decoder platform; tidak ada encoder AVIF |
      | SVG | Tidak didukung | Tidak didukung | `BitmapFactory` tidak membaca SVG; butuh AndroidSVG (belum ditambahkan) |
      | RAW | Terbatas (hanya DNG, tergantung perangkat) | Tidak didukung | decoder DNG platform; CR2/NEF/ARW tidak didukung, tanpa libraw |
      | TIFF | Tidak didukung | Tidak didukung | butuh libtiff/Apache Commons Imaging (belum ditambahkan) |
      | BMP | Didukung | Tidak didukung | decoder BMP platform; tidak ada encoder BMP |
      | PSD | Tidak didukung | Tidak didukung | layer PSD tidak dapat diparse; butuh library PSD |
      | PDF | Tidak didukung di tool ini | Didukung | tulis via `PdfDocument`; baca PDF→gambar ada di PDF Vault (`PdfRenderer`) |

      Status ini diuji `ImageGeometryGoldenTest` (`encodableFormatsAreExactlyThePlatformWriters`, `unsupportedTargetsAreRefusedWithReason`), jadi kode dan dokumentasi tidak bisa berbeda tanpa gagal test.


13. **Image Forge Batch 2 + Image Matrix (Fase 10): IMG-31–47**
    - **Satu pipeline filter untuk pratinjau dan ekspor**: `ImageFilterSpec` (preset, brightness, contrast, saturation, temperature, blur, vignette, tint) dikompilasi sekali di `ImageFilterPipeline.buildColorMatrix`. Empat preset dibangkitkan sendiri (17³, ±59 KB) sehingga tidak ada file LUT berlisensi pihak ketiga di APK.

Layer: gambar (dari Photo Picker, cache bitmap per URI), teks (warna + ukuran font), stiker/emoji. Ada urutan naik/turun, duplikat, visibilitas, blend, `LayerHistory` undo/redo (cap 50), serta 5 preset kanvas (1080², 1080×1350, 1920×1080, 1080×1920, 2048²). 15. **PDF Vault (Fase 12): PDFBox-Android + Tesseract4Android, dengan batas yang ditulis terbuka**
    - **Pemilihan library**: `com.tom-roush:pdfbox-android:2.0.27.0` (Apache-2.0) untuk semua operasi objek PDF dan `com.github.adaptech-cz.Tesseract4Android:tesseract4android-openmp:4.8.0` (Apache-2.0, JitPack — satu-satunya repositori artefaknya; API 4.8 memakai paket `com.googlecode.tesseract.android` dan `recycle()`, bukan `end()`) untuk OCR. iText dan MuPDF **ditolak** karena AGPL; PDFBox dipilih juga karena bisa mengenkripsi AES-256/AES-128/RC4-128 dan membaca AcroForm tanpa layanan cloud. Keduanya dicatat di `docs/LICENSES.md`.
    - **Operasi halaman tidak lagi merasterisasi**: implementasi Fase 8 (`PdfEngine.mergePdfs/splitPdfToZip/transformPdfPages`) merender tiap halaman ke bitmap 2×, sehingga teks hilang dan ukuran membengkak. FASE 12 menggantinya dengan `PdfVaultEngine` yang bekerja pada objek PDF asli (import halaman, atribut rotasi, content stream). Rasterisasi kini hanya dipakai bila memang perlu: kompresi, redaksi, OCR, dan slide PowerPoint.

Karena konten asli diganti gambar, **seluruh lapisan teks halaman itu hilang** — bukan sekadar ditutup kotak. Hasil dibuka ulang dan diekstrak teksnya; ringkasan melaporkan `verified` hanya bila istilah tidak lagi ditemukan. Konsekuensi jujur yang ditampilkan ke pengguna: halaman redaksi menjadi gambar (tidak bisa dicari/dipilih teksnya), dan kotak mengikuti perkiraan posisi karakter (rotasi halaman tidak lazim bisa bergeser beberapa titik).

Watermark yang sudah menyatu ke aliran konten **tidak** dihapus; bila tidak ada objek yang bisa dihapus, tool menyarankan PDF-14 (redaksi) alih-alih mengklaim berhasil. Batas ini juga tertulis di katalog dan deskripsi tool.

Karena tidak ada checksum publik per berkas, integritas diverifikasi dengan ukuran minimum 200 KB dan unduhan atomik `.part`; kegagalan jaringan menghasilkan pesan jelas, bukan teks kosong. OCR berjalan di `Dispatchers.IO` per halaman 200 DPI. Batas: akurasi bergantung kualitas pindai, dan pelatihan/penyesuaian bahasa tidak tersedia.

16. **Universal Converter (Fase 13): alias tanpa duplikasi, parser teks yang diuji, dan batas font/arsip yang ditulis terbuka**
    - **Alias benar-benar mendelegasikan**: `AliasTool` (CNV-01/02/04/05/07/08/09/11/12/15) tidak punya logika konversi sendiri. `inputSpec`, `params`, `requiresNetwork`, `requiresModel`, dan `dedicatedRoute` dibaca **lazy dari tool tujuan** (`ToolRegistry.findById`), lalu `run()` memanggil `delegate.run(ctx, input)`. Jadi satu implementasi punya dua pintu masuk dan perubahan parameter di tool asal otomatis ikut. CNV-13 adalah router tipis: `.docx` → PDF-07, selain itu → PDF-06. CNV-03 dan CNV-06 sengaja **bukan** alias karena kebutuhannya berbeda (4 format audio vs MP3 saja; FLAC/WAV 24-bit vs konversi umum).
    - **Tidak ada stub konverter yang tersisa**: `stubConverterTools()` dihapus dan `ToolRegistryTest` menegaskan `byGroup(CONVERTER).none { it.isStub }`. Total tetap 163 tool / 163 ID unik (28 di grup Converter).
    - **Keamanan arsip**: semua nama entri lewat `ArchiveEngine.sanitizeEntryName` — backslash dinormalisasi, segmen `.` dibuang, dan path absolut, `..`, drive letter, atau karakter kontrol **ditolak** (dicatat di laporan, bukan diekstrak). Hasil ekstraksi selalu ditulis ke ZIP keluaran, bukan ke filesystem pengguna, sehingga tidak ada jalur tulis di luar folder aplikasi. Zip bomb dibatasi berlapis: maksimum 4096 entri, 128 MB per entri, 512 MB total, dan rasio deklarasi >200× ditolak; batas juga dihitung ulang dari byte yang benar-benar dibaca agar header bohong tidak lolos. Kata sandi hanya hidup di memori selama operasi: tidak ditulis ke nama berkas, metadata ZIP, ringkasan hasil, atau log.
    - **AES-256 sekarang ZIP standar**: CNV-18 memakai zip4j (AES-256 + DEFLATE) sehingga hasilnya bisa dibuka 7-Zip/WinRAR, bukan format privat. ZIP ber-kata sandi dibaca lewat zip4j lalu ditulis ulang sebagai ZIP biasa; arsip `.hzm` lama (AES-256-GCM buatan Fase 8) masih bisa didekripsi agar berkas pengguna tidak hilang, tetapi enkripsi baru selalu ZIP AES-256.
    - **RAR hanya dibaca**: junrar tidak punya encoder, dan encoder RAR resmi proprietary. Karena itu CNV-17/CNV-20 menolak menulis RAR dan selalu mengeluarkan ZIP/PDF/EPUB. 7Z juga hanya dibaca (commons-compress + XZ); penulisan 7Z tidak didukung.
    - **EPUB realistis**: pembacaan mengikuti `META-INF/container.xml` → OPF → `spine`, teks XHTML diubah ke teks polos dengan entity decoding. EPUB ber-DRM dideteksi dari `META-INF/encryption.xml` dan **ditolak** dengan pesan jelas. EPUB → PDF memakai Helvetica (font asli buku tidak disematkan), dan EPUB keluaran komik adalah EPUB 3 minimal (tanpa CSS/nav bergaya). Gambar/CSS/tata letak EPUB tidak dipertahankan — tertulis di katalog dan deskripsi tool.
    - **Font: hanya yang bisa dibuktikan**. WOFF 1.0 ditulis/dibaca penuh (zlib per tabel, checksum tabel, `head.checkSumAdjustment` dihitung ulang). **WOFF2 ditolak** karena butuh Brotli + rekonstruksi transformasi glyf/hmtx. **OTF(CFF) ⇄ TTF ditolak** karena konversi outline CFF ke glyf butuh rasterisasi ulang glyph. Subsetting CNV-22 hanya untuk TrueType: cmap format 4/12 → glyph, penutupan komposit, penulisan ulang indeks komponen, `loca` long, `hmtx`/`hhea`/`maxp` diperbarui, tabel hinting/tata letak (fpgm/prep/cvt/GSUB/GPOS/kern/DSIG) dibuang. Batas ini bukan kegagalan tersembunyi: tool mengembalikan pesan penolakan yang eksplisit.
    - **Parser teks diperbaiki dan diuji**: CSV/TSV kini RFC-4180 penuh (kutip ganda, `""`, baris baru dalam sel, CRLF, tanpa baris palsu di akhir berkas). Markdown memproteksi kode inline/tautan sebelum escape sehingga `*` di dalam kode tidak berubah menjadi emphasis, mengelompokkan `<ul>/<ol>`, dan **menolak URL `javascript:`/`data:`/`vbscript:`** (berubah menjadi teks). GeoJSON menangani Polygon berlubang, MultiPoint/MultiLineString/MultiPolygon, dan GeometryCollection. STL mendeteksi binary dari ukuran pasti `84 + 50n` (bukan dari kata "solid", yang juga muncul di STL binary) dan memvalidasi float ASCII.
    - **Verifikasi fase ini**: tetap **statis** karena JDK/Gradle/Android SDK tidak tersedia. Yang dijalankan: pemeriksaan keseimbangan tanda kurung sadar-string/interpolasi pada seluruh berkas baru/ubah, pencocokan tanda tangan API terhadap sumber asli library (AndroidSVG 1.4, commons-compress 1.27.1, junrar 7.5.5, zip4j 2.11.5 diunduh dari Maven Central), dan tiga berkas test baru (`ConverterCoreTest` 16 test, `ConverterSuiteTest` 15 test, `ToolRegistryTest` diperbarui). **Tidak ada** `assembleDebug`, tidak ada uji konversi nyata pada ZIP/RAR/7Z/EPUB/font — itu langkah berikutnya saat toolchain tersedia.

17. **Core tools (Fase 14): MediaProjection per sesi, Keystore sebagai akar kepercayaan, backup berversi, dan cloud yang jujur soal batas**
    - **Screen Recorder memakai satu engine + satu service**: `ScreenRecorderEngine` memegang MediaProjection→VirtualDisplay→MediaCodec→MediaMuxer dan `ScreenRecorderService` adalah foreground service tipe `mediaProjection` (wajib; Android 14 menghentikan sesi bila service tidak bertipe benar). Izin persetujuan diminta **setiap sesi** lewat `createScreenCaptureIntent()` dan `resultData` diteruskan ke service — tidak ada penyimpanan token proyeksi. Jeda memakai `PARAMETER_KEY_SUSPEND` pada encoder video dan menghentikan aliran audio agar durasi jeda tidak ikut terekam.
    - **Audio layar apa adanya**: mic 48 kHz stereo, audio internal lewat `AudioPlaybackCaptureConfiguration` (API 29+) dengan usage MEDIA/GAME/UNKNOWN, dan mode gabungan melakukan rata-rata sampel tanpa resampling. Banyak aplikasi streaming/DRM menolak playback capture; bila kosong hasilnya senyap dan itu disebut di deskripsi, bukan diklaim berhasil. **Tidak ada** fallback diam-diam WebM→MP4: bila encoder VP8/Opus tidak ada, start gagal dengan pesan yang menyebut MP4 sebagai alternatif.
    - **Voice Recorder: FFT sendiri, encoder sendiri**: spektrum memakai FFT radix-2 (1024 sampel, jendela Hann, 40 pita log 40 Hz–16 kHz) di `SpectrumAnalyzer` — tanpa library FFT baru. WAV ditulis streaming dengan header dipatch di akhir (bukan menampung seluruh rekaman di memori seperti versi Fase 2). AAC memakai MediaCodec `audio/mp4a-latm` + MediaMuxer MP4; Opus memakai MediaCodec `audio/opus` + MediaMuxer WebM dan karena itu dibatasi API 29+. Penanganan panggilan memakai **fokus audio** (`AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`), bukan status telepon: hilang fokus otomatis menjeda. Konsekuensinya, panggilan yang tidak mengubah fokus audio mungkin tidak otomatis menjeda — batas ini disengaja agar tidak meminta izin READ_PHONE_STATE.
    - **Key Vault: Keystore adalah akar kepercayaan, bukan database**: kunci AES hidup di AndroidKeyStore dan tidak pernah diekspor; pasangan RSA/EC dibuat di perangkat dan **private key-nya disegel** kunci master Keystore `harimu_vault_master` (AES-256-GCM) sebelum masuk Room. Ekspor PEM memakai konfirmasi kredensial perangkat (`KeyguardManager.createConfirmDeviceCredentialIntent`, menampilkan biometrik/PIN) + peringatan eksplisit. Ini **bukan** `setUserAuthenticationRequired` pada kunci Keystore: mengikat kunci ke biometrik akan memaksa autentikasi pada setiap operasi AES (termasuk dekripsi berkas) dan tidak semua perangkat punya sensor, sehingga gerbang diletakkan di UI dan batas ini tertulis di layar serta katalog. Enkripsi berkas hanya untuk kunci AES (`HMVLT1|iv|ciphertext`); RSA/ECDSA dipakai untuk tanda tangan/verifikasi (`SHA256withRSA`/`SHA256withECDSA`). Verifikasi memakai alur dua langkah: pilih berkas asli, lalu berkas `.sig` yang dihasilkan saat menandatangani.
    - **Backup .omni berversi dan dimigrasikan**: `BackupEngine` menulis ZIP berisi `manifest.json` (skema 2, jumlah entri, parameter KDF) + settings/favorites/history + metadata kunci. Enkripsi `OMNIENC2` = salt16 + iv12 + iterasi4 + AES-GCM, KDF PBKDF2-HMAC-SHA256 **310.000** iterasi (naik dari 65.536 di Fase 2). Impor tetap menerima `OMNIENC1` (65.536) dan ZIP v1 yang bahkan tidak punya `vault_keys.json`, lalu memigrasikan manifes ke skema 2 (`migratedFrom` dilaporkan ke pengguna). Private key **tidak** ikut: kunci non-ekspor memang tidak bisa, dan kunci yang disegel terikat Keystore perangkat asal sehingga tidak berguna di perangkat lain — arsip hanya membawa metadata. Riwayat dibatasi 500 entri saat ekspor dan impor.
    - **Kredensial cloud disegel, bukan disamarkan**: `CloudCredentialStore` menyegel seluruh `CloudConfig` (access key, secret, refresh token) dengan `SecretBox` (AES-256-GCM, kunci AndroidKeyStore `harimu_secretbox`) ke `filesDir/cloud/credentials.bin`; tidak ada kredensial di DataStore, log, nama berkas, atau backup .omni. OAuth memakai **PKCE tanpa client secret** (Drive scope minimal `drive.file`, Dropbox `files.content.write/read`), redirect `harimu://oauth` ditangani deep link MainActivity, dan `state` diverifikasi sebelum penukaran kode. Access token diperbarui otomatis dari refresh token sebelum unggah; token hasil refresh disimpan kembali dalam bentuk tersegel.
    - **S3/R2: SigV4 yang bisa diuji**: `SigV4` menandatangani `PUT` objek dengan path-style `endpoint/bucket/key`, `host`, `x-amz-content-sha256`, `x-amz-date`, URI/query canonical, dan kunci turunan HMAC bertingkat. Vektor kunci penandatanganan AWS dipakai sebagai test. Batas: tanpa virtual-host style, tanpa multipart >5 GB, tanpa presigned URL. Drive memakai `uploadType=multipart` (satu permintaan, tanpa resumable); Dropbox memakai `/2/files/upload`; REST kustom mengirim multipart dengan nama field dan header JSON yang bisa diatur.
    - **Antrean unggah nyata, bukan tombol kosong**: `UploadQueue` menyalin berkas ke `filesDir/cloud_queue/` (bertahan saat cache dibersihkan), menyimpan status JSON, dan memproses berurutan dengan retry 2 s → 8 s → 30 s (maks 3 percobaan) untuk galat jaringan/5xx; galat 4xx langsung FAILED dengan pesan. Tombol “Unggah ke cloud” ada di `ResultCard` semua tool dan memakai koneksi aktif; bila belum dikonfigurasi, pengguna diarahkan ke Pengaturan. Batas: antrean dilanjutkan saat aplikasi memprosesnya lagi (tombol “Proses antrean”), **bukan** WorkManager, dan tidak ada unggahan paralel.

Yang dijalankan: skrip keseimbangan tanda kurung sadar-string/interpolasi pada semua berkas baru/ubah, serta `CoreToolsPhase14Test.kt` (16 test murni-Kotlin: vektor SigV4 AWS, canonical URI/query, header signPut, vektor PKCE RFC 7636, URL OAuth Drive/Dropbox, kebijakan retry, spektrum 1 kHz vs senyap, roundtrip/enkripsi/salah-sandi/migrasi v1/`OMNIENC1`/pemotongan riwayat). **Tidak ada** `assembleDebug`, tidak ada perekaman layar/suara nyata, tidak ada unggahan ke S3/Drive/Dropbox sungguhan — semua itu langkah berikutnya saat toolchain dan akun tersedia.
